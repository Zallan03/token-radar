How the model works

Model radar-2 scores every protocol from the snapshot’s own figures only. No protocol name is ever special-cased: the same function scores every row.

implied value = TVL × category multiple × growth × maturity × breadth

  • Category multiple — the median market-cap-to-TVL ratio of this snapshot’s own live-token protocols in the same category (at least 3 of them, else the global median), clamped to 0.05–1.50. The live market is the yardstick.
  • Growth — 1 + clamped 7-day TVL change (−50% to +100%) × 0.6.
  • Maturity — 0.7 + 0.3 × days listed (capped at 1,460); a protocol with no listing date counts as 365 days.
  • Breadth — 1 + 0.02 per extra chain, up to 5 extra chains.

What the board leaves out, and why

Wrapped, staked and bridged products of a token that already trades are not tokens still to come, so the board never ranks them as pre-token — even when the snapshot records no token for them. Versioned pools and exchanges are left out the same way. A protocol is called pre-token only in the sense that it records no token; the snapshot’s record is not proof it has none.
